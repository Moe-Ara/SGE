# SGE Game Engine - Physics and Event System Implementation

## Complete Documentation

This document provides a comprehensive overview of the physics engine and event system implementation for the Simple Game Engine (SGE).

## Project Overview

The implementation introduces a complete physics simulation system integrated with an event-driven architecture. This allows for realistic physical interactions within the game world while maintaining loose coupling between components through events.

## Architecture Design

### Core Physics Components

#### PhysicsEngine
- Central manager coordinating all physics operations
- Maintains collection of active physics components
- Processes time-based physics updates with delta time handling
- Integrates collision detection system with event publishing

#### BasePhysicsComponent
- Implements core physics properties (mass, velocity, acceleration)
- Provides force application and integration methods
- Handles position and rotation updates based on physics calculations
- Supports time-based simulation with proper delta time handling

#### SimpleCollisionSystem
- Implements AABB (Axis-Aligned Bounding Box) collision detection
- Uses BVH (Bounding Volume Hierarchy) for spatial partitioning optimization
- Generates collision events when object intersections are detected
- Supports different physics materials and collision properties

#### BVH (Bounding Volume Hierarchy)
- Spatial data structure for efficient collision queries
- Provides O(log n) lookup times for collision detection
- Supports dynamic updates for moving objects
- Optimized memory usage with smart pointer management

#### IPhysicsComponent Interface
- Defines contract for all physics component implementations
- Ensures consistent API across different physics types
- Enables polymorphic behavior for flexible component usage
- Supports extensibility for specialized physics requirements

### Event System Components

#### EventSystem
- Implements publish/subscribe pattern for loose coupling
- Thread-safe event processing with queue-based architecture
- Type-safe event handling using C++ templates
- Automatically publishes collision events from physics engine

#### IEventSystem Interface
- Defines required methods for event system functionality
- Enables substitution of different event system implementations
- Maintains consistent API across event system variants
- Supports future extensibility requirements

#### CollisionEvent
- Specialized event type for collision notifications
- Contains information about colliding objects and collision details
- Provides access to timing data and collision geometry
- Automatically generated by physics engine during detection

#### Event Base Class
- Common functionality shared across all custom events
- Built-in identification and timestamping capabilities
- Extensible design supporting new event types
- Unified interface for event handling operations

## Design Patterns Used

### Component Pattern
- Physics components attached to entities as needed
- Flexible architecture allows for mixed physics properties
- Easy to add/remove physics capabilities from objects

### Observer Pattern
- Event system implements observer pattern for decoupled communication
- Subscribers receive notifications without direct coupling
- Supports multiple listeners for same event type

### Factory Pattern
- Physics component creation supports polymorphic behavior
- Easy to create specialized physics implementations
- Flexible architecture for different physics requirements

### Template Method Pattern
- Event system uses templates for type-safe handling
- Base classes provide common functionality
- Derived classes implement specific behaviors

## Usage Examples

### Setting Up Physics Components
```cpp
// Create physics component
auto physics = std::make_shared<BasePhysicsComponent>();
physics->setMass(10.0f);
physics->setVelocity(glm::vec3(0, 0, 5));

// Attach to actor
actor.addComponent(physics);
```

### Event Subscription
```cpp
// Subscribe to collision events
eventSystem.subscribe<CollisionEvent>([](const CollisionEvent& event) {
    // Handle collision logic here
    std::cout << "Collision detected!" << std::endl;
});
```

### Physics Update Loop
```cpp
void update(float deltaTime) {
    physicsEngine.update(deltaTime);

}
```
